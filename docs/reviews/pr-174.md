## Findings and fixes

### P1: numeric-array hashes fail on the configured CI runtime

The hosted job at
https://github.com/LucaGenchi/opticalsetup/actions/runs/35831056752/job/107083500133
uses Node 22.23.2 and fails the hollow-core compressor golden test. Its four
differences are intensity-array digests for the before/after autocorrelators
and their repeated pulse-train records. The other 1,234 tests pass.

The unmodified revision passes all 1,235 tests locally on Node 24.19.0.
Running the golden tests with `node --no-use-std-math-pow` reproduces exactly
the four hosted digest pairs (`e1546782` → `820370d9`, `440bf314` → `0a7fcfd3`).
Comparing the rounded sample values between the two math backends gives a
maximum absolute difference of approximately `1e-20`, below the comparator's
existing `1e-18` absolute floor. Exact hashing bypassed that tolerance.

Long numeric arrays now retain every rounded sample in order instead of an
exact digest. The suite compares each sample with the existing tolerance:
`abs(a-b) <= 1e-6 * max(abs(a), abs(b), 1e-12)`. The summaries remain for
readability. Tests explicitly accept roundoff and tiny FFT tails while
rejecting swapped unsampled entries, meaningful amplitude changes, structural
changes and non-finite numbers. No tracer or physics code changes.

Seven snapshot files change representation. Across all 25 snapshots, every
previously recorded readable value and every non-array digest stays identical
to the reviewed revision. The only changes are replacing long-array digests
with complete ordered samples.

### P2: CLI checks disagree with the suite

`update-golden.mjs --check` previously compared serialized text exactly,
ignoring the suite's numeric tolerance, and did not reject orphan snapshots.
The CLI and suite now share the comparator. Orphans cause a nonzero exit and
name the obsolete file; the tool leaves deletion to the author. A disposable
fixture exercises deterministic generation, tolerant read-only checks, and
stale, missing, malformed and orphan snapshot failures.
